# Load Average

## Что это такое

`Load Average` — это метрика, отражающая текущую нагрузку на систему через количество задач, которые:

- выполняются на CPU
- готовы к выполнению (runnable)
- находятся в состоянии непрерываемого ожидания (uninterruptible sleep), чаще всего из-за операций ввода-вывода (I/O)

Load Average не является обычным арифметическим средним.
Это экспоненциально сглаженное среднее (EWMA), поэтому метрика обладает инерцией: недавние значения оказывают большее влияние, а более старые постепенно теряют значимость.

## Интервалы

Обычно выводятся три значения:

- за ~1 минуту
- за ~5 минут
- за ~15 минут

Пример:

    load average: 0.42, 0.71, 0.95

Это не точные средние за фиксированные интервалы, а сглаженные значения с разной глубиной “памяти”.

## Где посмотреть

- `uptime`
- `w`
- `top`
- `htop`
- `cat /proc/loadavg`

## Как интерпретировать

Смотреть `Load Average` удобно относительно количества логических CPU.

Примеры:

- для 1 CPU значение `1.00` означает, что ресурсы CPU полностью заняты
- для 4 CPU значение `4.00` соответствует полной загрузке системы
- если значение превышает количество CPU, часть задач ожидает выполнения

Важно учитывать, что Load Average отражает не процент загрузки CPU, а уровень конкуренции за ресурсы.

## Важные нюансы

- `Load Average` не равен `CPU usage`
- в метрику входят процессы, ожидающие I/O
- из-за сглаживания значения изменяются не мгновенно
- высокий `Load Average` при низкой загрузке CPU часто указывает на проблемы с диском или блокировки
- метрика учитывает задачи в состоянии `uninterruptible sleep`, которые нельзя прервать даже сигналами

Пример чтения метрики:

- `0.20 0.30 0.25` — система практически простаивает
- `6.00 5.50 5.10` на машине с 4 CPU — устойчивая перегрузка
- `8.00 2.00 0.70` — недавний резкий всплеск нагрузки
- `1.00 4.00 8.00` — нагрузка снижается

Смысл имеет не только абсолютное значение, но и динамика изменений.

## Практический вывод

`Load Average` используется как быстрый индикатор наличия проблемы, но не объясняет её причину.

Для дальнейшей диагностики обычно проверяют:

- `top`, `htop` — кто нагружает CPU
- `iostat`, `iotop` — есть ли задержки ввода-вывода
- `vmstat` — состояние очередей и блокировок
