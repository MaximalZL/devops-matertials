# Сигналы Linux

## Что такое сигналы

Сигналы в Linux — это механизм асинхронного уведомления процесса о событии. Сигнал может отправить:

- ядро
- другой процесс
- сам процесс себе
- пользователь через команды вроде `kill` или сочетания клавиш в терминале

Когда процесс получает сигнал, он либо обрабатывает его своим обработчиком, либо выполняется действие по умолчанию.

## Основные типы сигналов

Обычно выделяют две большие группы:

- стандартные POSIX-сигналы
- сигналы реального времени (`real-time signals`)

По действию сигналы часто делят так:

- завершение процесса
- завершение с созданием core dump
- остановка процесса
- продолжение выполнения
- игнорирование

Важно: `SIGKILL` и `SIGSTOP` нельзя перехватить, заблокировать или проигнорировать.

## Основные сигналы

- `SIGHUP (1)` — терминал закрылся или процессу предлагают перечитать конфигурацию
- `SIGINT (2)` — прерывание с клавиатуры, обычно `Ctrl+C`
- `SIGQUIT (3)` — завершение с дампом памяти, обычно `Ctrl+\\`
- `SIGABRT (6)` — аварийное завершение процесса
- `SIGKILL (9)` — немедленное принудительное завершение
- `SIGUSR1 (10)` и `SIGUSR2 (12)` — пользовательские сигналы для своих сценариев
- `SIGSEGV (11)` — ошибка доступа к памяти
- `SIGPIPE (13)` — запись в канал без читателя
- `SIGALRM (14)` — сигнал таймера
- `SIGTERM (15)` — штатный запрос на завершение процесса
- `SIGCHLD (17)` — уведомление родителя о завершении дочернего процесса
- `SIGCONT (18)` — продолжить выполнение остановленного процесса
- `SIGSTOP (19)` — остановить процесс

## Какие сигналы используют чаще всего

- `SIGTERM` — основной корректный способ завершить процесс
- `SIGKILL` — крайний вариант, когда процесс не отвечает
- `SIGINT` — остановка процесса из терминала
- `SIGHUP` — часто используется для перечитывания конфигурации демоном

## Основные команды

- `kill -15 <pid>` — отправить `SIGTERM`
- `kill -9 <pid>` — отправить `SIGKILL`
- `kill -HUP <pid>` — отправить `SIGHUP`
- `kill -l` — показать список сигналов
- `pkill nginx` — отправить сигнал процессам по имени
- `pkill -TERM nginx` — корректно завершить процессы по имени

## Практическое правило

Обычно процесс завершают так:

1. Сначала отправляют `SIGTERM`.
2. Ждут корректного завершения.
3. Только если это не помогло, используют `SIGKILL`.
